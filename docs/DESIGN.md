# 照片內容審閱工作台

專案階段：既有網站流程修訂。頁面類型：照片審閱工作台。核心使用者：11 位職安專家；核心物件：照片、AI 情境、最終危害、引用法規及案例、照片整體評分。

主要任務是直接對照 AI 與照片，完成自己固定的 30 張。入口為專家代碼網址；第一個決定是確認專家代碼。成功條件為四項整體判斷保存、提交並匯出。失敗時可重試保存或先匯出未保存草稿，換裝置以 JSON 恢復。

## 設計選擇

參考使用者指定的 Fefe9487/annotationtools GitHub index.html：藍色主要操作、淺灰背景、白色內容區、雙欄主畫面、頂部照片選擇與底部提交導覽。保留既有靜態 ESM 與 IndexedDB，沒有新增 runtime 框架或 CDN。

桌面左側照片與四項整體判斷，右側完整 AI 內容，占較多寬度。移除常駐 330 張任務側欄，以分配的 30 張下拉清單切換。照片可以放大拖曳。手機順序為照片、完整 AI 內容、整體判斷、底部提交；保留提交操作，不將長內容塞進窄欄。

資訊優先為照片、危害情境理由、法規／案例內容、四項整體判斷。所有情境理由、特徵、法規原文與案例摘要均直接可讀。危害類型捷徑只是頁內定位，沒有收合、彈窗或選單隱藏理由。

畫面用繁體中文與照片檔名，不展示磁碟路徑、schema 或演算法說明。所有判斷起始留空；未提供案例時免評並記錄 not_provided，不預設正確。沒有整張均正確的批次按鈕，也不要求負面判斷逐項填理由。

## 保存與恢復

十一組互不重疊，每組 30 張。依營造／製造配額與最終危害數平衡分組，固定分組版本。公開網站的代碼是進度識別，並非存取限制。

正式新版、QA 新版與舊版資料保存空間分開，原始資料不刪除。備份綁定資料集、照片 SHA-256、專家與分組版本。保存成功以 IndexedDB transaction 完成為準；游標保存失敗不推翻已成功保存的評分。其他分頁更新造成 revision 不符時停止覆寫，提示匯出與重新載入。

## 風險與驗證

主要風險為長條文造成閱讀負擔、畫面推論被當成事實、原始多類型情境對應漏失、窄螢幕表單擠壓、變更版號後遺失舊評分。直接保留原文、明確標示來源限制、943 個情境完整性檢查、v1 保留及獨立 QA 空間回應這些風險。

驗證包含 11×30 無重複覆蓋、330 圖文與照片雜湊、全部 943 原始理由直接出現在生成 HTML、四項判斷驗證、330 筆匯出還原、不同專家／QA 隔離、歷史版本、分頁衝突及匯入 transaction 回滾。真正的布局、點擊、刷新、下載、匯入與手機操作仍須瀏覽器驗收；工具被保存的拒絕設定阻擋時不宣稱通過。
