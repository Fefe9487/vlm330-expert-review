# VLM330 照片危害辨識專家審閱

[正式網站](https://fefe9487.github.io/vlm330-expert-review/) · [11 位專家入口](docs/EXPERT_LINKS.md)

11 位專家 A01–A11 各審閱固定的 30 張照片，互不重複，合計涵蓋 330 張。每位看過 AI 結果後，完成四項照片整體判斷：危害辨識正確性、危害完整性、法規適當性、職災案例適當性。補充意見選填；不要求逐條法規或逐段案例標註。

網站沿用 [annotationtools](https://github.com/Fefe9487/annotationtools) 的藍色操作、淺灰底、白色內容區與雙欄布局。每項危害的 AI 原始情境理由及相關特徵直接展示，沒有收合選單。法規原文、案例摘要、改善建議、防護具與立即危險判定也直接保留。

## 專家操作

判斷基準見 [標註指引](docs/標註指引.md)。

1. 開啟自己的專家入口，確認代碼。
2. 對照照片與完整 AI 內容；點照片可放大。
3. 選擇四項整體判斷。選「部分正確／不正確／部分適當／不適當」時，會出現可複選的問題項目清單，標示哪個危害、法規或案例有問題。勾選後可寫該項的問題。選「不正確」或「不適當」時，勾選的每一項都要寫原因，否則不能提交；選「部分正確／部分適當」時可以留空。「查看」可定位完整內容。選「有漏報」時，可新增額外漏報項目，每筆從 17 種具體危害選一類，並選填情境或位置；可新增多筆，也可補登同類型的不同情境。
4. 點「提交並繼續」。完成 30 張後匯出 JSON 評分檔回傳。
5. 進度自動保存在目前瀏覽器。換裝置前匯出 JSON，之後匯入恢復。回傳給研究團隊的也是這份 JSON。

專家代碼用於區分進度，沒有帳號驗證。照片及 AI 報告已依使用者同意公開；評分只存在各自瀏覽器 IndexedDB，不會自動傳回 GitHub 或研究團隊。

## 分組與彙整

十組各有營造 20 張、製造 10 張；A11 為營造 19 張、製造 11 張。分組依待評閱讀量拉平：整體描述、情境理由、法規條文與職災案例。A01–A10 約 63,300–64,000 字，A11 約 53,000 字，是最少的一組。改善建議沒有單獨分數，不計入這個閱讀量。

固定分組版本為 disjoint30-b45a53e2590d，清單位於 data/manifest.json。專家清單、切換照片、完成度與備份均限定分配的 30 張；備份綁定照片雜湊、資料集及分組版本。舊分組的瀏覽器草稿不會帶進新分組。

專家頁不提供多人彙整。主持人另行收齊 11 份 JSON 再統計。重複匯入同一份備份不會增加筆數；可只補缺少資料，或更新較新的版本，更新前保留歷史答案。

本次每張照片只有一位專家評分，結果可報告照片層級的整體判斷。問題勾選用於指認需檢查的內容；未勾選的項目不自動視為已逐項確認正確。無法計算專家間一致性、逐項引用正確率、逐危害 precision／recall／F1，也不能推定未列出漏報類型時的正確危害集合。

## 漏報補登的 17 類

分類版本 vlm330-concrete17-v1，採用既有危害清單中的 17 項具體類型：墜落、滾落；跌倒；衝撞；物體飛落；物體倒塌、崩塌；被撞；被夾、被捲；被切、割、擦傷；踩踏（踏穿）；溺斃；與高溫、低溫之接觸；與有害物等之接觸；感電；爆炸；物體破裂；火災；不當動作。

每筆補登有獨立 ID、危害類型及選填情境說明，與 AI 原始內容分開保存。新增空白列可先保存草稿；提交前需選類型或移除空白列。有漏報但尚未補登時仍可維持原整體判斷，不自動推定漏報內容。

切換完整性判斷會保留已輸入資料，供切回「有漏報」繼續編輯。僅有漏報時啟用這些項目；CSV 只列啟用且已選類型的補登，JSON 同時保留未啟用草稿，解讀時應依 completeness 欄位判斷。舊版整體評分沒有這些欄位仍可匯入與還原。

## 原始資料與舊版評分

使用指定修訂版的 330 張原圖：營造 219 張、製造 111 張。照片按原始位元組複製，未裁切或重新壓縮。資料集 vlm330-20261008-7396811ccfe0 包含 943 個原始情境、1,285 個最終危害項目與 2,375 段案例摘要。

原始理由依危害類型對應到最終危害，多類型情境可在多個危害下出現。找不到原始理由的最終增列類型明確註記；沒有對應最終類型的原始情境另行展示。未自行新增理由或修正 AI 答案。

AI 提供的法規內文也是待評估內容，官方連結供查核。法規以 2026-10-08 有效版本為基準；職災案例缺少原始來源，只能先評估情境及致災機制的適切性。

新版使用獨立的 v2 保存空間。舊版逐項評分留在原資料庫，可在「我的進度與備份」另行匯出；舊 JSON 也可匯入保留。舊答案不會自動換算成四項整體評分，也不列入新版 30 張完成度。先前已填四項整體判斷的新版進度與 JSON 則繼續相容；未勾問題項目不會被推定為所有引用都不適當。

## 本機與驗證

運行需 Node.js 20 以上；網站運行沒有外部 CDN 或 npm 套件依賴。執行 npm start 後開啟 http://127.0.0.1:8133。

開發檢查先 npm ci，再 npm test；另以 python scripts/validate_site.py 核對 330 張照片、內容與分組。fake-indexeddb 僅供 Node 測試使用。53 項測試包含 13 項舊版相容規則、19 項新版／儲存檢查、11 項問題項目選擇、說明、必填原因、定位、保存、匯出與相容性檢查，以及 10 項漏報補登與分類、草稿、匯出還原檢查，不能代替真實瀏覽器畫面驗收。

網址加上 ?qa=1&expert=A07 可進入獨立操作測試空間；QA 匯出不能匯入正式評分。正式專家入口不含 qa=1。

重新產生資料需 openpyxl、來源 Excel 與營造／製造照片子目錄，使用 scripts/build_dataset.py。資料集及分組版本改變時不得混用舊答案。
